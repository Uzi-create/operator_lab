# 专用画面运动测试

这个界面用于实测 `estimate_scene_motion`：选择静态背景区域，观察逐帧位移、拒绝原因和耗时，并保存可复查的输入与结果。

绿色箭头表示**上一帧到当前帧的画面运动**，单位为原始采集图像的像素。右侧轨迹是当前连续有效片段内的画面位移累加，不能当作机器人三维位置。静态场景下，相机向右平移通常表现为背景向左；相机旋转、不同深度的物体和运动前景需要单独分析。

## 启动

在仓库根目录运行（依赖沿用仓库的 NumPy/OpenCV）：

```powershell
# 无相机演示：已知平移真值，120 帧后结束，包含空白拒绝与恢复
python projects/camera/live_motion.py --demo

# USB 相机，默认编号 1；内置摄像头通常使用 0
python projects/camera/live_motion.py --camera 1 --width 1920 --height 1080

# 在另一台电脑上离线重放拍摄的视频
python projects/camera/live_motion.py --video scene.avi

# 无窗口验证：保存合成数据、原始/叠加视频及报告
python projects/camera/live_motion.py --demo --headless --frames 120

# 无窗口限帧采集；必须指定帧数，避免无意中持续录制
python projects/camera/live_motion.py --camera 1 --headless --frames 300

# 固定分析区域：原图左上角 (160, 100)，宽 640、高 360
python projects/camera/live_motion.py --camera 1 --roi 160 100 640 360
```

`--width/--height` 是相机请求尺寸或合成图尺寸；相机实际输出尺寸以界面和报告为准。输入视频保持原分辨率。`--analysis-width 480` 控制算子内部分析尺寸，返回位移仍以原始输入像素计量。`--frames 0` 表示读到视频结束；合成模式默认 120 帧；交互相机模式持续运行到退出。

## 操作

| 操作 | 鼠标 / 快捷键 | 行为 |
| --- | --- | --- |
| 选择背景 | 在图像内按住左键拖动 | 固定矩形 ROI，至少 96 × 96 个原图像素；黑边不能作为起点 |
| 使用全图 | Full frame / F | 清除 ROI，切换后下一帧重新建立参照 |
| 重置轨迹 | Reset / R | 清除累计值与前后帧关系 |
| 暂停 / 恢复 | Pause / 空格 | 暂停时不录制重复帧；恢复后重新建立参照 |
| 结束 | Quit / Q / Esc / 关闭窗口 | 关闭采集、写完报告、解码检查保存的视频 |

青色框表示实际分析 ROI，橙色曲线表示当前连续有效段。绿色箭头只在算法接受结果时显示；为了看清小位移，箭头长度按 8 倍显示，超过预览范围时截到图像边界，面板和日志中的位移数值保持原始像素单位。低于 2 像素的位移显示绿色圆点。首次参照帧、拒绝、暂停和重置不会显示绿色运动箭头。拒绝后的下一次有效估计开启新段，不跨越失败帧接线。输入分辨率改变时退回全图并重新建立参照。

ROI 是屏幕上固定的图像区域，不会跟随物体移动。选择有纹理、尽量同一深度、没有移动前景的背景；相机移动后需要检查该区域是否仍然适用。面板中的 `Candidate` 只是诊断候选值，拒绝时不代表有效测量。纯重复纹理、低纹理、明显独立前景运动等情况下出现拒绝，比自信地画出错误箭头更合理。

合成演示每帧正向或反向平移 `(4, -3)` 像素，每 120 帧中的第 48～52 帧（从 0 计数）为空白，随后恢复纹理。空白及刚恢复的第一帧没有可见对应特征，因此不计算精度误差。

## 输出与计时

默认每次运行都在 `projects/output/camera/motion/` 下创建独立目录。`--output 路径` 可以指定输出父目录；`--no-video` 只保留 JSONL、CSV、汇总报告。

- 原始视频保留所有处理过的输入帧，使用 MJPG 有损编码；叠加视频保存固定 1280 × 800 的界面，可回看箭头、ROI、拒绝原因和轨迹。
- `frames.jsonl` 保留完整逐帧记录，CSV 用于表格筛选，`summary.json` 汇总接受/拒绝原因、耗时分位数和视频解码校验结果。
- 输入尺寸改变时视频分片；编码需要时只在右/下边缘补齐偶数尺寸，记录保留真实输入尺寸。
- `API` 是算子调用耗时，`Preprocess + API` 还包括输入转换和会话处理。
- `read_ms` 是读帧耗时（合成模式包含生成图像），`render_ms` 是界面绘制耗时；`frame_ms` 包括读取、会话处理和界面绘制。
- `video_write_ms` 是视频写入开销；`loop_ms` / `recorded_frame_ms` 为 `frame_ms + video_write_ms`，不包含 JSON/CSV 刷盘、GUI 等待或人工暂停。界面 `Last full frame` 显示上一帧从读取开始到日志写完的实际耗时，包含视频与日志写入。
- AVI 按标称输入帧率播放，因此相机暂停或处理过慢时，播放时长不等同实际采集时长。相机记录时间是读帧结束后的单调时钟，并非传感器曝光时间；普通视频重放用帧号/标称帧率建立均匀时间轴，不声称保存了可变帧率视频的原始时间戳。`timestamp_source` 明确区分来源。
- 只有 `--demo` 的受控合成输入有位移真值，能够计算像素误差；真实相机与普通视频的通过率不等于准确率。
- 无法打开相机或视频时也会留下失败报告；命令返回非零，避免把空输出当作通过。
- 视频实际解码帧数少于容器声明时会报告提前读断；不提供帧数的容器只能按读取结束处理，不能据此证明整个源文件完整。
- `source_timeline_frame_rate_hz` 来自输入时间轴；对于视频/合成输入，它反映名义时间轴，不是实际处理吞吐。时间戳倒退或重复时不生成该帧率值。

## 建议的实拍顺序

1. 固定相机看静态背景：观察零位移抖动，正常应以圆点为主。
2. 缓慢左右和上下平移：检查背景方向和箭头一致，同时记录实际分辨率、API / 整帧耗时。
3. 逐步提高移动速度：观察接受率和拒绝原因，不用单个高响应值证明方向正确。
4. 保持相机静止，让手或物体经过前景：比较全图与静态背景 ROI 的表现。
5. 单独测试旋转、模糊、遮挡、重复纹理，保存失败片段供后续优化。

这些人工观察不能证明亚像素准确度；需要真实精度数字时，应另配有已知位移或外部参考的采集装置。
