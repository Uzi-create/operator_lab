# 三维对应点定位与圆柱测量：验证和性能记录

发布整理日期：2026-10-22。下列算法验证和计时于 2026-10-11 在 Windows 本机完成；发布前重新核对源码 SHA-256，与记录中的两个算子、演示及基准脚本一致。结果适用于这些合成输入，不代表真实传感器精度或跨机器速度。

## 功能与优化

- `estimate_rigid_transform_robust`：从已有对应关系的三维点求刚体位姿，处理部分错误对应。三点 RANSAC、Kabsch 精修、退化检查和最终全点残差都保留。优化让初始全点精修得到的内点比例也参与自适应停止，避免已经有好解仍跑满随机预算。
- `fit_cylinder_known_axis`：输入外部已知的轴方向，测圆柱半径、轴线、角覆盖和可见支持跨度。半径范围参与候选搜索，避免尺寸不合要求但点数更多的圆柱遮住合法目标。短弧、支持不足、轴向跨度不足等返回拒绝。

两者使用 NumPy 底层矩阵运算和 Python 有界 RANSAC 调度，本批没有新增自写 C++ DLL 内核。定位不负责发现对应点；圆柱不搜索未知轴方向，也不测物理端盖距离。

## 完整 API 性能

Python 3.11.4、NumPy 2.2.6、OpenCV 4.12.0，Windows AMD64。CPU 标识和源码哈希保存在[原始基准 JSON](geometry_validation_20261011/benchmark.json)。每项预热 3 次，交替顺序运行 21 次；计时包含输入检查、RANSAC、精修和最终残差，不包含采集、显示及对应点搜索。

| 算子与输入 | 中位耗时 | P95 | 优化前中位耗时 | 中位加速比 |
| --- | ---: | ---: | ---: | ---: |
| 定位，1500 点，30% 错配 | 6.643 ms | 9.281 ms | 147.534 ms | 22.21 倍 |
| 定位，10000 点，30% 错配 | 20.050 ms | 21.801 ms | 317.737 ms | 15.85 倍 |
| 圆柱，1500 点，20% 杂点 | 4.986 ms | 6.320 ms | — | — |
| 圆柱，10000 点，20% 杂点 | 14.235 ms | 16.453 ms | — | — |

这两个定位基准中，随机轮数由 512 降到 17，返回矩阵完全相同，内点掩码完全相同，残差在 `1e-12` 以内一致。另有 20 组独立种子对照，新结果的真值预测误差均未增加。自适应随机停止仍可能在其他输入上选到不同候选，不能把这些结果解释成所有输入逐位一致或绝不漏检。

本机计时存在波动；JSON 保留全部样本，本表使用中位数而非最快样本。这里是同进程优化前后对照，不是 Windows/macOS 硬件对比，也不能直接换算成相机或机器人系统帧率。

## 验证证据

- 全库 356 项 Python 测试、C++ 原生断言通过，其中新增算子专项 27 项。
- 28 组演示全部完成，178 张 PNG 成功解码；新演示 PNG、HTML 和 JSON 已生成并检查。
- [独立审计 JSON](geometry_validation_20261011/audit_results.json)：87/87 场景通过，包含多种随机种子、噪声与错配、大坐标偏移、平面/近共线边界、反射/缩放拒绝、圆柱短弧/薄片/错轴、半径约束、多种输入布局及资源上限。
- 最终矩阵/轴线与返回的残差、内点掩码和 RMS 经独立重算核对。

首次受限沙箱运行在临时目录的 `os.replace` 上出现 27 个权限错误；保留错误日志后，在正常权限下运行相同验证命令全部通过。未通过删除测试或改变原子写入逻辑规避问题。

示例的 1500 点合成场景中，定位旋转误差约 0.01234°、平移误差约 0.03968 mm，圆柱半径误差约 -0.00882 mm。它们是已知真值下的数值结果，不能作为现场测量精度承诺。杂点恰好落在同一无限圆柱上时仍是径向内点，可能扩大可见跨度；本例约 0.409 m 的支持跨度不是生成时 0.32 m 的物理管长。

## 在目标电脑复现

```text
python -m pip install -r requirements.txt
python -B verify.py --demos
python -B projects/vision_robot/demo_correspondence_cylinder.py
python -B projects/benchmarks/benchmark_correspondence_cylinder.py --repeats 21
```

跨电脑默认构建不加 `--native`。只运行新算子回归可用 `python -m unittest operators.tests.test_correspondence_ops operators.tests.test_cylinder_ops -v`。

默认基准测当前源码；可选 `--baseline <早期correspondence_ops.py>` 用于同进程历史对照，并先核对这两个基准输入的矩阵、残差和掩码。记录中的旧文件 SHA-256 保存在 JSON，历史源码保留于原工作区，不是默认运行依赖。

接口和使用边界见[组合示例说明](CORRESPONDENCE_CYLINDER.md)、[定位接口](../../operators/docs/CORRESPONDENCE_POSE.md)、[圆柱接口](../../operators/docs/CYLINDER.md)。这批新增算子的 macOS/Linux 独立运行与真实相机、扫描仪、机器人验证尚未完成。
