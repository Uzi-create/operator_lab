## 新增算子

### 双侧细线响应 ridge_response

对每个像素 c，在四个方向、三个半宽（1/2/3 工作像素）取两侧像素 p、q：

```text
a = c - p
b = c - q
response = max(0, min(a,b), min(-a,-b))
```

只有两侧同时比中心亮，或者同时比中心暗，响应才为正。
在理想单调梯度和台阶上为零，细亮线/细暗线有响应。
这可以抑制部分单侧明暗变化；真实反光条带同样可能产生双侧响应，不能因此完全消除误报。

C++ 核心在 `../metal_ridge.hpp`，Python API 在 `inspect_surface_v2.py`。
可调用 `ridge_response(gray, backend='native'/'numpy'/'auto')`。
输入 float32 灰度 [0,1]，输出同尺寸响应；非连续 NumPy 视图会在 native 路径转为连续内存。
未构建新动态库时 auto 回退到 NumPy。不同平台的速度关系需要重新测量。

性能优化是把边界处理移到独立循环，内部使用连续访问及无符号分支的 min/max 运算。
首版带逐像素条件分支的 C++ 比 NumPy 慢，已被上述实现替换。
本机 720×960 固定随机图、交替顺序运行 9 次的中位数：
C++ 1.89 ms，NumPy 9.63 ms，约 5.1 倍。包含 API 校验与输出分配。
这只比较等价的 ridge_response，不是整套检测的提速倍数。

### 按整个连通区域复核

用 v1 划痕候选像素作为候选集合，统计双侧响应 >=0.06 的原形态学响应权重占比。
占比 >=0.60 保留整个区域，否则整块进入 rejected_v1_pixels。
使用响应权重而非简单像素比例，避免一条清晰细线周围的弱响应像素让它被拒绝。
不逐像素切碎候选，因此不会由于该复核把一个旧区域拆成多个新框。

此门限仍可能拒绝较宽、单侧或低对比度的真实损伤。保留移除证据图用于检查漏检。
没有根据人工标注评估 precision/recall，因此候选减少不代表误报一定减少。

### 单独的边缘复核带

v1 内缩 16 工作像素；v2 增加距离 ROI 边缘约 7~16 像素的独立复核带。
采用短范围 ridge 而不是 v1 的大窗口形态学，避免用跨越 ROI 的大窗口响应来判断。
该带仍会检出轮廓反光，结果单列为 border_review_candidates、紫色 B 框。
它不计入内部 scratch_candidates，也不自动判定缺陷或合格。
最靠边的 7 像素、过暗及过曝区域依然不检；没有声称消除了所有边缘漏检。

可视对照显示部分旧候选被移除，主要划伤附近仍有候选；纹理与轮廓反光仍存在。
色斑流程复用 v1，没有新增氧化化学判定，oxidation_confirmed 仍为 null。

## API 示例

```python
from inspect_surface_v2 import inspect, Refinement

report, maps = inspect(image_bgr, metal_roi,
                      refinement=Refinement(ridge_floor=0.06,
                                            min_supported_fraction=0.60))
print(report['scratch_candidates'])
print(report['border_review_candidates'])
```

图像与 ROI 契约同 v1。新增地图：ridge_response、rejected_v1_pixels、border_review_mask。
report.ridge_backend 表示实际使用的底层实现。边缘框和内部框都是原图像素坐标。
