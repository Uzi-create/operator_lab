# 跟随与避障算子性能审计

审计日期：2026-10-28。用户的目标平台是 Xavier NX，目前没有可用实物。本次数据来自 Apple M4、16GB 内存、macOS arm64、Apple Clang 21 的 CPU 合成测试；未连接相机、雷达或底盘，也未运行检测网络或 ROS 节点。

## 测试方法与原始数据

基线为 Git 提交 `253782d`。同一份基准源代码分别包含基线与优化后的头文件，均使用 `-std=c++17 -O3 -DNDEBUG -Wall -Wextra -Wpedantic -Werror`。没有开启 fast-math，没有降低图像分辨率、雷达点数、候选速度采样数或碰撞/制动检查精度。

每项先执行 5 次预热，再进行 101 次测量；极短算子每次计时批量执行 10 或 100 次后按调用次数摊分。共 3 轮，轮间交替优化前后的顺序，串行运行，避免两个基准竞争 CPU。测试程序通过结果摘要与编译器屏障约束死代码删除/跨次移动；分配计数会引入少量测量开销。

- p50：三轮中位数的中位数。
- p95、p99：各轮分位数中的最大值，不是把三轮原始样本混合后的分位数。
- `cold_ms`：该算子第一次调用的耗时，输入已创建；不表示冷启动整个程序或冷 CPU 缓存。
- `new_calls_per_op` / `new_bytes_per_op`：通过可替换 C++ new 申请的次数和累计字节数；**不是峰值存活内存、RSS，也不覆盖直接 malloc、驱动或 GPU 分配**。
- 图像中包含背景、目标、侧面表面、深度噪声与缺测；另测 float32 图像和 1200 个小块的碎片化场景。雷达使用 721 / 2000 条射线、可选去畸变，局部规划还测试 2000 个障碍返回点及绕障场景。大图像数据为原始 uint16 深度，float32 测项单独标注。

原始逐轮 CSV、编译器信息、头文件内容哈希和完整比较表保存在 [本轮结果](benchmarks/results/m4_20261028/manifest.json) 与 [comparison.csv](benchmarks/results/m4_20261028/comparison.csv)。

## 优化内容及代价

1. 深度区域新增 `DepthRegionWorkspace`。独立调用可传入工作区，`RgbdTracker` 默认持有并复用它，避免每帧重建深度缓存、访问标志、队列和统计缓冲。返回的区域/像素仍由返回值自己拥有，不引用工作区。工作区保留历史最大容量，每个并发调用需有独立实例；独立工作区的 `clear()` 释放容量，Tracker 析构时释放其内部工作区，`reset()` 保留缓存以便再次选择目标。
2. 大块 uint16 深度区域使用原始 16 位编码的精确频率统计，计算加权中位数和 MAD；不会把米制深度近似分桶。使用相同的原始值到 double 的舍入，保留代表像素与其真实深度的对应关系。浮点输入使用通用精确路径；小块采用选择算法，均匀块有精确快速路径。工作区增加了最多 65536 桶的计数与活跃桶缓存。
3. 碰撞检查缓存一次姿态所需的 SAT 几何量；自由单元不再做无用的几何准备。车体已占据区域的清除限定在其局部包络，仍保留整格包含判断，且不清除 occupied 单元。
4. `check_trajectory(..., braking_only, record_path)` 新增末尾可选参数 `record_path`，默认 true 保持原接口结果。设为 false 只跳过诊断路径的存储，仍执行所有碰撞样本、反应延迟和完整制动尾段。局部规划不保存每个候选的路径，最终赢家按同样参数重算并保留路径；最终速度仲裁的独立复查仍然执行。
5. 候选速度数组预留容量；端点净空评分复用一次逆变换，并跳过确定无法减小当前最小净空的 hypot 运算。不会跳过轨迹碰撞检查。
6. 激光配置验证不再临时分配一张栅格；障碍点数组按射线数预留容量。射线从图内起点离开矩形地图后结束自由空间采样，保留此前相同采样点、传感器盲区、未知空间和障碍优先级。地图外的真实返回点仍保留在观测点列表中。
7. 目标关联先做位置门控，再在一个可复用临时数组中进行原来的外观归一化；远离预测位置的候选不再分配、归一化完整向量。外观门限、歧义拒绝和匹配评分不变。

## 正确性核对

比较脚本在计时之前分别编译两份 `differential.cpp`：相同种子下检查 12000 个旋转外形查询、450 条轨迹、40 组含无效值的扫描、45 组深度区域/深度带、80 组关联输入以及 30 组局部规划。摘要包含返回状态、阻挡格、浮点输出、完整区域像素及获选轨迹；本轮两版本摘要逐位一致。每个性能测项的结果摘要也必须一致，否则脚本失败。

新增回归测试用独立完整排序核对 uint16、float、double 的中位数/MAD，包括奇偶样本数、极小/极大缩放、无效帧、跨度/步长和跨帧工作区复用；另核对局部车体清除与完整遍历的结果，以及记录/不记录轨迹时相同的碰撞判定和结束状态。原有跟踪、遮挡、扫描时效和避障测试仍需通过。

最终实际仓库验证结果：356 项原有 Python/项目测试、5457 项既有 C++ 检查、304970 项新增统计/工作区/轨迹回归检查通过；AddressSanitizer/UBSan 通过；34 帧 RGB-D 回放和 6 场景共 630 帧导航闭环回放通过。验证入口为 `verify.py --sanitizers`，未连接硬件。

数值对照是本次有限输入和编译器下的证据，不是对所有输入的形式化证明。源码回归、合成闭环和硬件安全验证有各自边界。

## 在 Xavier NX 上复测

不需要实物传感器即可先运行单版本基准，仍需取得 NX 才能测其 CPU：

```sh
make -C operators/cpp benchmark
# 若只测指定项目：
operators/cpp/build/operator_benchmark --iterations 101 --filter rgbd_tracker
```

有 Git 历史和 Python 3 时可运行完整 A/B 审计。Python 仅用于开发期编排，不进入机器人算法运行链：

```sh
python3 operators/cpp/benchmarks/compare.py \
  --baseline 253782d --rounds 3 --iterations 101 \
  --output projects/output/nx_performance_run1
```

输出目录必须是新建或空目录。脚本只读查询可用的 `nvpmodel -q`、`jetson_clocks --show`，记录环境，不改变 NX 功耗模式或频率。对比时应使用一致的电源、散热和功耗设置，记录后台负载，并观察持续运行后的尾部延迟。

本轮不能给出 Xavier NX 的真实帧率。Mac 的耗时不能直接移植为 NX 指标；本测试也不包含模型推理、图像传输、ROS 同步/TF、调度延迟和底盘响应。后续仍要用真实 RGB-D/激光数据验证目标识别稳定性，再实测外参、延迟、制动与运动安全。
